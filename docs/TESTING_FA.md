# Qio Desktop — راهنمای تست ویندوز و مک

## وضعیت
کیو یک نسخه در حال توسعه است. رابط شناور، هفت حالت انیمیشنی، شناسایی تاریخچه محلی Codex/Claude و خواندن اختیاری فعالیت از پل محلی DotPals کدنویسی شده‌اند. این **به معنای آماده بودن نسخه نهایی یا موفقیت تست Build نیست**.

## ساخت خودکار
GitHub → Actions → **Qio desktop build** → آخرین اجرا. اگر سبز شد، فایل خروجی را از بخش Artifacts همان Run دریافت کنید. روی macOS برنامه بدون امضای توسعه‌دهنده ممکن است محدودیت Gatekeeper داشته باشد؛ برای انتشار عمومی نیاز به signing/notarization است.

## استفاده بدون DotPals
Qio پوشه‌های نشست `~/.codex/sessions` و `~/.claude/projects` را محلی می‌خواند. تشخیص تاریخچه به معنی اجرای زنده Agent نیست.

## اتصال اختیاری DotPals
اگر DotPals را جداگانه نصب و اجرا کنید و پل آن روی `127.0.0.1:5175` فعال باشد، Qio در پنل بازشده داده‌های خلاصه `GET /api/activity` را به صورت خواندنی نمایش می‌دهد. هیچ دستور تأیید، رد، اجرا یا تغییر تنظیمات به آن ارسال نمی‌شود. نسخه Qio هیچ فرایندی را خودکار نصب یا اجرا نمی‌کند.

مرجع: https://github.com/Rikinshah787/dotpals

## تست دستی
1. روی Windows و macOS پنجره را باز کنید، جابه‌جا کنید و بین حالت کوچک/بزرگ تغییر دهید.
2. بررسی کنید پنجره همیشه روی سایر پنجره‌ها باشد و متن‌ها فارسی نمایش داده شوند.
3. انیمیشن‌ها و گزینه کاهش حرکت را امتحان کنید.
4. بدون نصب ابزارهای AI مطمئن شوید برنامه پیام «شناسایی نشده» می‌دهد.
5. بعد از ساخت نشست محلی در Codex/Claude بررسی کنید فقط وضعیت تاریخچه عوض شده، نه اینکه ادعای کار زنده داشته باشد.
6. اگر DotPals را اجرا کرده‌اید، پنل فعالیت را بررسی کنید؛ در حالت خاموش بودن DotPals باید حالت عدم اتصال نمایش داده شود.
7. نتیجه Build را جدا برای Windows و macOS ثبت کنید و خطاهای احتمالی را در Issues مخزن قرار دهید.

## محدودیت‌های باقی‌مانده
- تأیید/رد درخواست‌های Claude و Codex هنوز پیاده‌سازی نشده و نباید به عنوان قابلیت آماده معرفی شود.
- بررسی کامل Diff و تست‌ها فقط با داده‌های اثبات‌پذیر و بازبینی سازگاری نسخه‌های Agent امکان‌پذیر است.
- اعلان بومی، auto-update، tray و سازوکار امضا هنوز کامل نیستند.
